# ControlLab 架构（M1）

## 一句话

前端负责「输入 + 展示」，后端负责「算」，一次请求返回整页所需数据；桌面外壳只做进程托管，不参与业务。

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│  React + TS + ECharts      │  POST  │  FastAPI                     │
│  ─ 输入降幂系数             │ ─────► │  /api/v1/analyze             │
│  ─ 极点零点 / 阶跃曲线      │ ◄───── │  services/analyzer.py        │
│  ─ 判据与指标               │  JSON  │   ├ core/transfer_function   │
└────────────────────────────┘        │   ├ core/stability           │
                                      │   └ core/time_response       │
                                      └──────────────────────────────┘
              ▲                                    ▲
              │ 静态 dist                          │ 子进程托管
        ┌─────┴────────────────────────────────────┴─────┐
        │ desktop/launcher.py：选端口 → 起 uvicorn →     │
        │ 轮询 /health → Edge --app 打开窗口 → 收尾      │
        └───────────────────────────────────────────────┘
```

## 为什么是「单端点 + 一次算完」

M1 的所有信息都依赖同一组系数：稳定性、极点、阶跃响应互相印证。拆成多个端点会让前端管理多次请求的时序与错误，也会出现「图已经画了但判据还没回来」的不一致。
一次返回的代价是响应体较大（约 450–600 个采样点），实测在局域网回环下 **< 20 ms**，可接受。

## 后端分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `app/main.py` | 建 app、CORS、挂载 `frontend/dist`、`/health` |
| 路由 | `app/api/routes.py` | 参数校验后的调用与异常 → HTTP 422 映射 |
| 模型 | `app/schemas/analysis.py` | Pydantic 请求/响应模型（`extra="forbid"`） |
| 编排 | `app/services/analyzer.py` | 串起各 core 模块、生成 warnings、组装响应 |
| 算法 | `app/core/*` | 纯函数，无 IO，可单独测试 |

`core` 不依赖 FastAPI，可以直接在脚本里 `from app.core.stability import build_routh_table` 复用。

## 算法决策

### 1. Routh-Hurwitz：精确有理数 + ε 法 + 全零行特判

- 系数经 `Fraction(str(x))` 转成精确分数（`0.1` → `1/10`），再变为 `sympy.Rational`。
  直接用 float 时，`[0.1, 0.2, 0.1]` 这类输入在某些列会算出 `±1e-17`，造成假变号——这是教学软件里最不能接受的错误。
- **首列为 0 且整行不全为 0**：把首元素替换为符号 `ε`，后续行按公式继续算；最后对第一列每个元素取 `lim(ε→0⁺)` 的符号来数变号。
- **整行为 0**：说明存在关于原点对称的根（通常是一对虚轴根）。用上一行构造辅助方程 `A(s)`，对其求导后替换该行，继续算；同时标记 `special_case = all_zero_row`，提示「临界稳定，非渐近稳定」。
- 表内元素以 `sympy` 表达式保存，输出时 `sstr` 成字符串，前端直接渲染 `"1/5"`、`"ε"` 这类精确值。

### 2. 稳定性结论：两条独立判据 + 互相校验

```
verdict = classify_by_roots(poles)      # 极点实部（数值）
sign_changes = build_routh_table(den)   # Routh 变号（符号）
```

- 极点判据：`max Re > 1e-6` → 不稳定；存在 `|Re| ≤ 1e-6` → 临界稳定；否则稳定。
- 两者矛盾时写进 `warnings`，提示可能是数值病态。不静默选择其中一个。

### 3. 时域指标

| 指标 | 定义 |
| --- | --- |
| 稳态值 | 终值定理 `num(0)/den(0)`；`den(0)=0`（含积分环节）则为 None |
| 超调量 | `(ymax − yss)/|yss| × 100%` |
| 峰值时间 | `argmax y` 对应时刻（超调 > 0.1% 才给） |
| 上升时间 | 欠阻尼：首次到达 `yss`；过阻尼：10%→90% |
| 调节时间 | 最后一个满足 `|y − yss| > band·|yss|` 的采样点之后一帧 |
| 稳态误差 | 单位阶跃下 `1 − yss`（0 型系统） |

- **不稳定/临界稳定时指标一律不返回**（`defined: false`）：数值仿真此时是发散的，算出来的「超调量」没有意义，教学场景下误导性极强。
- 仿真时长：`8/|最慢极点实部|`，向上取整到 0.1 s，限制在 0.1–5000 s；用户可用 `t_end` 覆盖。
- 采样 900 点，按步长降采样到 ≤ 600 点后返回。

### 4. 非真分式

`np.polydiv` 做多项式除法，阶跃响应只对严格真分式部分仿真（商多项式是冲激项，不属于阶跃响应曲线），并在 `warnings` 里说明；响应体额外返回 `quotient_expr` 供前端展示。

### 5. 频率响应与稳定裕度

- 频率网格：`np.logspace(log10(ω_min), log10(ω_max), 400)`；默认范围由极零点的模长决定（`scale/100 → scale*100`），保证既覆盖低频增益段，也能看到高频滚降。
- 直接对 `H(jω)` 求值（`scipy.signal.freqs`），幅值取 `20log10|H|`，相位 `unwrap` 后转成角度，避免 ±180° 跳变把曲线画断。
- 稳定裕度：
  - `ωc` 由幅频曲线穿越 0 dB 求得，`ωg` 由相频穿越 -180° 求得；
  - 穿越点用**对数频率线性插值**（曲线在对数坐标下近似直线），比取最近采样点精确一个数量级；
  - γ = 180° + ∠H(jωc)，Kg = -L(ωg)。
- 系统非渐近稳定时，裕度只有形状意义，analyzer 会额外写一条 warning 提醒。

### 6. 根轨迹

对每个 K 解特征方程 `D(s) + K·N(s) = 0`：

1. **系数对齐**：`N` 左侧补零到与 `D` 同长，才能做数组相加；
2. **K 扫描**：几何等距取 320 点（低 K 更密，能看清离开极点的方向）；自动 `K_max` 的做法是不断倍增，直到最远闭环极点的模到达特征尺度的 8 倍；
3. **分支跟踪**：第一个 K 的根按 (Re, Im) 排序作为初值；后续每个 K 的根用**最近邻贪心匹配**接到已存在的分支上（同阶系统根数恒等于分母次数，不会出现分支增删）；
4. **临界增益**：记录每个 K 下所有根的 `max(Re)`，找到它由负变正的区间，在对数 K 上线性插值——与 Routh 判据得到的临界增益互相印证（例如 `1/(s³+2s²+2s)` 得 K≈4，Routh 给 `0<K<4`）；
5. **返回**：`branches[i][j]` 与 `gains[j]` 一一对应，前端据此在 tooltip 里显示该点的 K。

### 7. 前端图表

| 图 | 实现要点 |
| --- | --- |
| 极点零点 | 散点 + 右半平面 `markArea` 淡红；坐标轴范围按模长取「好看刻度」 |
| 阶跃响应 | 折线 + 稳态 `markLine` + ±band 两条虚线 + 峰值 `markPoint` |
| Bode | 一个 ECharts 实例两个 grid：上幅频、下相频，共用 `type: "log"` 的 x 轴；`ωc`/`ωg` 竖线用 `markLine` |
| Nyquist | 正频率实线 + 镜像虚线；`(-1, j0)` 用红色菱形标注；坐标范围按幅值 80 分位裁剪，避免低频渐近线把有用区域压扁 |
| 根轨迹 | 每条分支一条 `line` 序列（颜色区分），叠展开环极点/零点；临界点用 scatter 标记；坐标范围取所有轨迹点模长的 75 分位，避免远端把原点附近压扁 |

### 8. 公式编译（v0.3）

`core/formula.py` 把 `wn^2/(s^2+2*zeta*wn*s+wn^2)` 这样的文本编译成 `num/den` 系数：

1. **归一化**：`^` → `**`，全角括号、`×÷−` 等替换成 ASCII。
2. **预注册标识符**：正则扫出所有 `[字母][字母数字]*`，逐个登记为 `Symbol` 放进 `local_dict`。
   这一步不能省——sympy 的隐式乘法变换会把未登记的 `wn` 拆成 `w*n`。
3. **解析**：`parse_expr` + `implicit_multiplication_application`（支持 `2s`、`3(s+1)`），
   `global_dict` 只放 `Integer/Float/Rational/Symbol/Mul/Add/Pow` 白名单，挡住任意代码执行。
4. **代参数**：未在 `params` 里给出的参数取 1.0，所以滑块还没出现时也能先算出一版结果。
5. **取分子分母**：`together` 合并分式后 `fraction` 拆分，再 `Poly(..., s).all_coeffs()` 拿降幂系数。
   **不做 `simplify`**：它会约掉公因子，把 `(s+1)/(s³+6s²+11s+6)` 变成 `1/((s+2)(s+3))`，与用户输入不符。
6. **错误处理**：解析失败、次数 > 20、分母恒为 0、参数非有限值都抛 `ValueError` → 422，前端在输入框下方提示。

前端只保存「公式文本 + 参数表」，每次拖动滑块都重新提交 `{formula, params}`，由后端编译后再走同一套分析流水线；
响应里的 `parameters` 用于生成滑块（只补缺失项，避免请求循环）。

### 9. 框图求解（v0.4，Mason 增益公式）

框图本质上就是信号流图，因此不做「等效变换化简」，而是直接套 Mason 公式：

1. **节点语义**：`input` / `output` / `sum`（比较点）/ `takeoff`（引出点）/ `block`（环节）。
2. **增益归属**：环节的传递函数挂在它的**出边**上（入边增益 1），这样一个节点只有一条出边时可以直接连乘，多出边时（引出点）各分支自然共享同一信号。
3. **比较点符号**：比较点每条入边带 `sign = ±1`，因此「回路增益」天然带上负号，不需要额外判断正负反馈。
4. **前向通路**：从 input 出发 DFS，不重复经过节点，到达 output 即记录并停止（避免穿过输出再绕回）。
5. **回路**：对每个起点做 DFS，回到起点即成立；去重规则是「起点取回路中 id 最小的节点」，并在扩展时只接受 `target > start`，保证每个回路只被枚举一次。
6. **特征式**：`Δ = 1 - ΣL_i + ΣL_iL_j - ΣL_iL_jL_k + …`，其中「互不接触」用节点集合两两不交判定，组合用 `itertools.combinations` 枚举（回路数 > 12 时跳过高阶项）。
7. **残式**：`Δ_k` = 删去与前向通路 P_k 接触的所有回路后，剩余回路的 Δ。

得到的 ΣP_kΔ_k / Δ 再走原有的 `compile_gain` → 多项式 → 与 `num`/`den` 输入完全相同的分析链路。
规模上限（30 节点 / 80 边 / 60 通路 / 40 回路）用于防止指数爆炸；无输入、无输出、无通路都返回 422 并附中文原因。
同一对节点之间重复画的连线在 `analyze_diagram` 里按 `(source, target)` 去重，否则回路会被数多次、Δ 直接算错。

### 10. 框图连线：直角路由（v0.5）

不用 React Flow 的贝塞尔边，改为自绘 `OrthogonalEdge`（`frontend/src/components/diagram/OrthogonalEdge.tsx`），只输出 `M/L` 指令：

1. **端点向量**：根据 `sourcePosition` / `targetPosition` 得到出端与入端的朝向，先沿朝向走 `STUB = 18px` 直段，再开始折线，因此箭头总是垂直进入节点。
2. **三类走法**：
   - 水平 → 水平（同向）：在两端中点做一次 Z 形折线；
   - 水平 → 水平（反向，例如反馈绕回左侧）：下沉 `LANE = 70px` 到一条通道，再横向折回，避免与主通路重叠；
   - 竖直 → 竖直 / 水平 → 竖直：单折点，用于「引出点底部 → 环节 → 比较点底部」的反馈环。
3. **微抖动抑制**：两端手柄高度差 ≤ 3px（布局取整误差）时不拉台阶，直接画一条水平线——这是默认示例能画出教科书效果的关键。
4. **符号徽标**：沿入射方向退 16px、再向侧面让开 11px，避免压住箭头；`pointer-events: all` 才能点到。
5. **手柄布局**：比较点有左（主通路）与底（反馈）两个入端，引出点有右（主通路）与底（反馈）两个出端；环节可 `flipped`，右进左出，用于反馈支路上的 H(s)。

## 前端结构

```
App.tsx                     布局 + 输入状态 + 工作模式（?mode=diagram）+ URL 参数化（?num=&den=&formula=）
├─ CoefficientInput         系数输入（系数模式）
├─ ParameterSliders         未知参数滑块 + 精确数值框（公式模式 / 框图模式）
├─ FormulaView              G(s) 分式排版
├─ diagram/DiagramCanvas    React Flow 画布（Provider + Inner，因为 useReactFlow 必须在 Provider 内）
│  ├─ diagram/DiagramNodeView  输入/输出胶囊、比较点 ⊗（圆圈内一个叉）、引出点、环节矩形
│  ├─ diagram/SignedEdge       ±1 徽标连线，点击切换极性
│  └─ diagram/MasonPanel       前向通路 / 回路 / Δ 展开
├─ StabilityPanel           特征方程 + 结论卡 + 三重依据 + Routh 表 + warnings
├─ MetricsGrid              6 个指标卡
├─ StepResponseChart        曲线 + 稳态线 + 误差带 + 峰值标注
├─ BodeChart                幅频/相频双 grid
├─ NyquistChart             正频率 + 镜像 + 临界点
├─ RootLocusChart           分支 + 开环极点零点 + 临界增益
└─ PoleZeroChart            s 平面散点，右半平面着色
```

- 图表统一走 `components/useEChart.ts`：`echarts.init` + `ResizeObserver` + `setOption(option, true)`。
- 请求走 `hooks/useAnalysis.ts`：260 ms 防抖、`AbortController` 取消上一次请求、按请求 JSON 做内存缓存（同参数不重复算）。
- 类型 `types/analysis.ts` 与后端 schema 手工对齐（M1 不引入代码生成）。
- 样式为手写 CSS（设计变量 + 卡片体系），不引入 UI 框架，避免打包体积与学习成本。

## 桌面外壳

`desktop/launcher.py`：

1. `pick_port()` 绑定 `127.0.0.1:0` 拿系统分配的空闲端口，避免端口冲突；
2. 用 venv 里的解释器起 `uvicorn app.main:app --host 127.0.0.1 --port <p>`；
3. 轮询 `/health` 直到 200（最长 30 s），后端进程提前退出则立即失败；
4. 用独立 `--user-data-dir` 启动 Edge `--app=http://127.0.0.1:<p>`，保证窗口关闭时进程树随之结束；
5. 窗口退出后 `terminate()` 后端，`finally` 中兜底回收。

不选 pywebview 的原因见 `docs/dev-setup.md`：本机 pythonnet 无法加载 `Python.Runtime.dll`，属于环境限制而非代码问题。`--app` 模式零依赖、窗口观感接近原生。
